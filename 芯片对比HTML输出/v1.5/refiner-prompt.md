# Refiner 精修复审 Prompt（USER）

你是资深前端审查与精修工程师。输入是一份已生成的单页 HTML（Tailwind CDN），请你以「对标 Gemini Canvas 的惊艳 / 高密度 / 强交互单页」为总目标，**只做保守优化、不做重写**，输出精修后的完整 HTML（纯 HTML 文本流，无 ``` 围栏、无解释文字）。

## 总目标与契约

本页面的质量由 system 的 **6 条成功标准**定义，你做它们的**第二道验收**：逐条检查 HTML 现状，**只修复不达标的项，不动已达标的项**。

- **密度**：4-6 区块、每区块 ≥6 数据单元是否都在？——勿增删区块。
- **可操作**：≥3 个联动交互是否都**真能跑**（点击有反应、是纯函数联动）？死按钮必须修。
- **惊艳**：配色对比是否足够、视觉层次是否清晰？在不改配色方案前提下优化层次与质感。
- **清晰**：文字 ≥14px、对比度足、选中态不遮挡内容？
- **完整**：到 `</html>` 无占位符 / 无 `...` / 无 TODO 残留？
- **可信**：真实数据未被改动，示例仍带标注，演示数据免责声明仍在？

## 硬性约束（不可违反）

- **不改结构**：不增删、不重排 `<section>`，不改动文案事实（产品名 / 功能 / 价格须与输入一致；Context 已提供原始事实供核对）。
- **不改交互逻辑意图**：只修「实现 bug」，不重设需求。
- **安全**：不得引入 `localStorage` / `sessionStorage` / `alert` / `confirm`；若发现原 HTML 误用，改为内存变量 + 页面内 toast。
- 输出**纯 HTML**（以 `<!DOCTYPE html>` 开头、到 `</html>` 结尾），无 ``` 围栏、无解释、不新增注释。
- 若 HTML 已满足全部 6 条标准、无明显缺陷：**原样输出**，不要为改而改（避免越改越差）。

## 精修前自检（因 thinking 已关闭，须显式逐项打勾）

对照 6 条标准逐条检查，只列出需要修复的项并修复，已达标的跳过；重点排查关 thinking 后易翻车的几类：

- 交互是否真联动（点选 / 勾选有反应，不是死按钮）；
- 是否误用 localStorage / alert / confirm（沙箱会崩，改内存变量 + 页面内 toast）；
- 对比表 / 图表是否真有数据（非空壳）；
- 文字 ≥14px、对比度足、选中态不遮挡；
- 有无 `...` / TODO / 占位残留。

> 这是 Second-pass 验收，不是重写。守住「只修不重写」，即使精修不理想，上游原始 `html` 仍可安全回退。
